Motivation

The Research Problem

  • NASA SnowEx (2017–2023): a multi-year field campaign to measure snow properties across diverse landscapes
  • Ground measurements collected for validation of airborne and satellite remote sensing
  • Rich, structured datasets — a natural fit for a relational database

The Data

The SnowEx Database

Structure

  • PostgreSQL with PostGIS spatial extension
  • Normalized relational schema with multiple tables
  • Tables for snow depth, density pits, spectral reflectance, and more
  • Linked by common keys: site name, date, coordinates

Why PostgreSQL?

Spatial queries, complex joins, and ACID compliance for research-grade data integrity

What's Inside

  • Measurement values with units and uncertainty
  • Metadata: instrument type, observer, protocol
  • Geographic coordinates and site descriptions
  • Temporal coverage across multiple field campaigns

The Challenge

Database lives on EC2 — collaborators need a clean, scalable API to query it

The Challenge

Database Access

Previous Approach

  • Required local CLI client installation
  • Distributed AWS credentials to all users
  • Security concerns with credential management
  • User environment configuration burden

Lambda Solution

  • Secure, passwordless API access
  • No credential distribution needed
  • API Gateway handles authentication
  • Clean separation of concerns
